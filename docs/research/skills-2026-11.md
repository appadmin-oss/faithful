# Which skills Faithful ships, and why

Researched 20 Nov 2026 from primary sources where possible. Items marked [u] were not
confirmed at the source and are not relied on for rules.

## The ecosystem

- **Spec** (https://agentskills.io/specification): `name` ≤64, lowercase-hyphen, equals the
  folder; `description` ≤1024 and says what AND when; body under 500 lines / 5k tokens.
- **Claude Code** (https://code.claude.com/docs/en/skills): description cut at 1,536
  characters; the whole skill listing shares about 1% of context, least-used descriptions are
  dropped first — every skill costs every session, so Faithful keeps descriptions under 400
  characters and leads with the user's own words.
- **Anthropic best practices**
  (https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices): third
  person, assume the model is smart, validate → fix → repeat loop, evals before writing.
- **Vercel's eval** (https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals):
  skills unused by default in 56% of runs; an AGENTS.md index reached 100%. Hence `init`'s
  AGENTS.md block names every skill.
- **Most-installed UI skills** (https://skills.sh, figures as shown on the day): anthropics
  `frontend-design` 1.1M, vercel `react-best-practices` 917K, `web-design-guidelines` 885K,
  `impeccable` 422K, `ui-ux-pro-max` 462K. They teach taste or rules and end in the model's
  own judgement or a Lighthouse score. Only impeccable ships a detector, for slop tells.
  None proves states, responsive behaviour, invisible upgrades or token use. That is the gap.

## What people complain about (2025–2026)

Ranked by how many independent sources raise it (judgement, not a count):

1. Agents ignore the design system and invent components (21st.dev, Aug 2026,
   https://21st.dev/blog/why-agents-invent-components; ZURB,
   https://radar.zurb.com/article/your-agent-isnt-listening-and-nobodys-checking).
2. Hardcoded values and token drift (https://dev.to/oqa/vibe-coding-problems-7-visual-bugs-ai-code-generators-always-ship-37mf).
3. Missing states: hover, focus, disabled, loading, empty, error
   (https://blog.logrocket.com/generating-the-feature-with-an-ai-coding-assistant/; an
   "NN/g 92% no empty state" figure is secondhand [u]).
4. Inaccessible custom controls (https://blog.master.dev/ai-generated-ui-is-inaccessible-by-default/;
   PACE, ASSETS '26, https://faculty.washington.edu/wobbrock/pubs/assets-26.04.pdf).
5. Broken at phone and in-between widths
   (https://dev.to/kaplich/i-analyzed-100-vibe-coded-websites-and-found-these-common-mistakes-5275).
6. Unrequested regressions during edits (https://news.ycombinator.com/item?id=47912642).
7. Dark mode broken by hardcoded colours (https://dev.to/pavelbuild/light-mode-was-lying-to-us-217b).
8. Invented data and social proof
   (https://dev.to/agent_paaru/i-deleted-1462-lines-from-my-landing-page-heres-what-was-in-them-15m0).

## Rules the skills teach, and their sources

- WebAIM Million 2026 (https://webaim.org/projects/million/): 95.9% of home pages fail;
  missing form labels on 51%, empty buttons 30.6%, low contrast 83.9%.
- WCAG 2.2: 2.5.8 target size, 2.4.11 focus not obscured, 3.3.8 accessible authentication,
  1.4.10 reflow, 1.4.4 resize (https://www.w3.org/WAI/WCAG22/Understanding/).
- First rules of ARIA (https://www.w3.org/TR/using-aria/).
- GOV.UK validation and error messages
  (https://design-system.service.gov.uk/patterns/validation/,
  https://design-system.service.gov.uk/components/error-message/). NN/g allows validation on
  blur (https://www.nngroup.com/articles/errors-forms-design-guidelines/); the skill follows
  GOV.UK and allows blur, never per keystroke.
- Empty states and progress (https://www.nngroup.com/articles/empty-state-interface-design/,
  https://www.nngroup.com/articles/progress-indicators/).
- Viewport units (https://web.dev/blog/viewport-units), safe areas
  (https://developer.mozilla.org/en-US/docs/Web/CSS/env).
- Vercel Web Interface Guidelines
  (https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/README.md):
  tabular numbers, `Intl` formatting, URL state, no disabled-in-advance submit.

## Shipped (each ends in a command that proves it today)

| Skill | Proof |
|---|---|
| faithful-ui-states | `audit` on every state URL |
| faithful-responsive | `audit --viewports 320…1440` |
| faithful-no-visual-change | `verify <before-url> --build <after-url>` + `parity` |
| faithful-design-tokens | `guard` + `verify tokens.json --build` |
| faithful-data-display | `audit` (unrendered values, dummy data, clipping) |
| faithful-accessible-forms | `audit` + `parity` + a keyboard walk, reported |
| faithful-dark-mode | `audit --color-scheme both` (text contrast, light native controls) |
| faithful-i18n | `audit --stress expand,rtl,spacing` (pseudo-localised text by the W3C expansion ratios, https://www.w3.org/International/articles/article-text-size; a `dir=rtl` render; WCAG 1.4.12 text spacing — each followed by the existing clipping, overlap and sideways-scroll checks) |

## Not shipped yet, and what would let them ship

- **Full accessibility**: axe-core inside `audit` (HANDOFF next step 3); until then
  `faithful-accessible-forms` says plainly that the keyboard walk is manual.
- **Motion**: Faithful renders with reduced motion and cannot measure animation; leave it to
  emilkowalski/skills.
- **Taste**: owned by frontend-design and impeccable; `faithful-ui-quality` covers slop.
